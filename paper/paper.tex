\begin{abstract}
  We provide a relatively simple transformation between the Demand and Clairvoyance semantic models for cost analysis of lazy evaluation using functional logic programming. This improves on the highly manual and brittle method for translation between the semantics implemented in prior work. We provide an Agda proof that the transformation is functionally correct and time-cost equivalent\lai{TODO: Change this when we get the exact bound - do we have equivalence, or near-equivalence?}.

\end{abstract}

\section{Introduction}

In functional logic programming, one program contains two semantics: a
``forward'' nondeterministic semantics with \emph{choices}, and a ``backward''
demand-driven semantics with \emph{free variables}. Past research has shown the
usefulness of this feature in different contexts.\ly{TODO: Citations.} In this
paper, we demonstrate yet another useful application: lazy cost analysis.
Specifically, we show that two different semantics proposed independently for
reasoning about the computation cost of lazy functional programs, 
clairvoyance semantics~\cite{clairvoyant,forking-paths} and demand
semantics~\cite{bjerner1989,demand-semantics}, can both be represented using a single functional logic program.

In lazy evaluation, a computation is driven by its demands, performing only the operations strictly required to compute a given result. Computations are
stored as \emph{thunks} that are only evaluated when their values are demanded.
Even then, computations are only evaluated to the extent that's
sufficient for its demand. This prevents the execution of extraneous operations, but results in infamously challenging cost analysis. For example\lai{Is this example the best one to start with, or should I start with one we are going to use again later? It's my favorite easy example, at least}, suppose that we define the \emph{Selection Sort} and \emph{Head} functions in the obvious ways.\lai{Should we give an actual definition, or leave it abstract like this to save space?} Then, say that we want to compute the following (where xs is an arbitrary list):

\(head (selection\_sort xs)\)

At first glance, one unfamiliar with laziness\lai{I think it's funnier to say this than the arguably more correct "one familiar with lazy evaluation"} might expect this to take \(O(n^2)\) average time, as is typical for \emph{Selection Sort}. However, since the algorithm will always search for the largest element first\lai{Do we need to mention smallest-first selection sort?}, the leading element will always be put in place before any others. Hence, if we are only demanding the head of the list, computation can stop after one iteration, and the time complexity falls to \(O(n)\). Eager evaluation strategies cannot take advantage of this fact, but lazy evaluation does.

One major drawback of laziness becomes apparent when we consider how partially executing a function call interferes with traditional cost analysis methods. Shortcutting (or even failing to run) functions runs counter, in particular, to the concept of \(O\)-notation. Technically speaking, every function takes \(O(1)\) time in a lazy language, as it is always possible to call a function and then never demand its output. For example, if we call \(head (selection\_sort xs))\) as part of a larger function that never uses the resulting element of xs, then the call would be stored in a \emph{thunk} and not further evaluated. As \emph{thunk} creation is a constant-time operation\lai{... it is, right?}, this results in the aforementioned \(O(1)\) time cost. This is not a particularly \emph{meaningful} thing to say about a lazy function, but its truth renders much of the existing paradigm for cost analysis nearly useless in the realm of laziness.

This paper will focus on two cost models which address this problem - \emph{Demand Semantics} and \emph{Clairvoyance Semantics}. Some other models will be explored briefly in Section whatever-number-is-related-work\lai{TODO: What number is this, anyway?}, but are not the focus of our work.

Clairvoyance Semantics models a lazy program as a nondeterministic tree of possible execution paths. The concept was first introduced in \cite{clairvoyant} and implemented in Rocq in \cite{forking-paths}\lai{Is this how we will do inline citations, and how we will reference them in the text?} via the Clairvoyance Monad. To analyze cost within this model, we utilize this monad to simulate nondeterministically choosing which thunks to continue forcing and which to skip, eventually resulting in a path which mimics the path of a function computing the same output. \lai{TODO: add more detail and corrections here - maybe we can use figures like those in the Forking Paths paper?}. \lai{Do we need a concrete example here?}

Demand Semantics, on the other hand, models the cost lazy programs by computing how much of the input must be forced to produce a function's output, which is provably cost-equivalent to computing the same output. First described in \cite{bjerner1989} and formalized in Rocq in \cite{demand-semantics}, the idea is also relatively straightforward, but is quite different from clairvoyance semantics in imlpementation. Rather than involving nondeterminism directly, the 'choices' made in a function's execution path are abstracted away into an "outD" input, which models the output demand. outD is then fed to a separate cost-analysis function derived from the original function in a systematic way. Finally, the cost analysis function uses outD to compute the answer to a different query than the original function - how much of the input was needed to compute outD? It turns out that this computation results in the same time cost as computing the input normally, making it a helpful model for lazy cost analysis.\lai{How about here?}

While clairvoyance and demand semantics provably produce equivalent cost analyses, directly translating from one to the other is challenging.\lai{Maybe two paragraphs - one outlining the problem, and another introducing the idea of using FLP to solve it.} There is certainly some amount of 'clairvoyance' occurring in demand semantics in the literal sense, as one needs to know what demands will be placed on the output before cost analysis can proceed (in order to construct a meaningful outD). However, the handling of nondeterminism is left implicit - we take as premise that one will know which sorts of output demands a user might wish to reason about, and say little about how they came to possess that information. Clairvoyance semantics has a similar issue, but in reverse\footnote{After we introduce the main ideas of the functional logic translation between the two, the fact that clairvoyance and demand semantics are inverses of each other in this way will likely seem somewhere between ironic and prophetic.}. The concept of "demand" is not explicitly mentioned in the semantics, but nondeterministically choosing a program's execution path is also, \emph{implicitly}, very similar to computing that same path using the output demand as a guide \lai{Feels like I'm not explaining this quite well enough. I'll think about it.}.

While this conundrum left us (as researchers interested in lazy cost analysis) at an impasse\lai{too informal?}, those familiar with functional logic programming concepts may have already noticed the connection that eventually led us through it. Functional logic languages which integrate nondeterminism, like Curry\lai{What do I cite here...?}, have a notion of forward and backward execution that maps neatly onto the aforementioned relationship between demand and clairvoyance semantics. Is this mapping correct, though? Yes, we have discovered, and provably so.

Our contributions are as follows:
\begin{itemize}
\item A conceptual link between forward and backward execution and the relationship between clairvoyance and demand semantics for cost analysis of lazy evaluation.
\item A means by which to translate between the two models in a straightforward way using Curry, with examples.
\item Proof, formalized in Agda, that the transformation between models is functionally correct and preserves time-cost estimates.

\end{itemize}

% The standard semantics for call-by-name uses a heap that binds variables to
% expressions; evaluating a variable amounts to evaluating the expression to
% which it is bound and then updating the heap to bind the variable to the
% resulting value. This is attractive because it reflects a straightforward
% implementation of call-by-name evaluation on an actual computer, but it has
% the drawback that it is non-compositional; that is, a derivation is not
% generally a simple composition of subterm derivations. Therefore, some have
% tried to develop semantics that are equivalent but also compositional.

% An early example is the \emph{demand semantics} of Bjerner and
% Holmstr{\"{o}}m. In this semantics, an open term is represented as a function
% that takes, in addition to a list of variable bindings, a \emph{demand} on the
% value to which the term will ultimately reduce; it produces a list of demands
% on its free variables. The demand represents, essentially, ``how much'' of the
% result will end up being used by the rest of the program. This semantics was
% originally presented without types; a version with types was published in
% STORYOFYOURLAZYFUNCTIONSLIFE.

% Another example of compositional semantics is the \emph{clairvoyance
% semantics} of Hackett and Hutton. The key idea of this semantics is that, when
% binding a variable to an expression, rather than deferring computation of the
% bound expression until it is needed, we \emph{immediately} choose
% nondeterministically to either evaluate the expression or discard the binding
% entirely. This semantics is equivalent to the standard semantics in the sense
% that, if \( t \Downarrow v \), then there is some derivation of this fact that
% is cost-equivalent to the derivation of the same in the standard semantics;
% and, furthermore, this derivation is the minimal such derivation.

% In STORYOFYOURLAZYFUNCTIONSLIFE, the fact that demand semantics is equivalent
% to the standard semantics was established by proving equivalence to
% clairvoyance semantics, which had already been proven equivalent to the
% standard semantics. However, this led to some difficulties with mechanized
% proofs. These proofs required writing demand functions by hand, a tedious and
% error-prone process. In fact, it required writing three versions of ``the same
% term'': a pure version, a clairvoyance version, and a demand version. Thus, we
% sought alternate means of expressing demand functions. In particular, we hoped
% to be able to write a term \emph{once} and automatically obtain the
% clairvoyance and demand versions of that term.

% Eventually, we hit on the idea of using \emph{functional logic programming}.
% Functional logic programming is a paradigm that combines the fundamental
% computational framework of functional programming with the nondeterminism and
% free variables found in logic programming.

% Our key idea is that, in a functional logic language, we can use
% nondeterminism to express directly the ``clairvoyance behavior'' of a term,
% and we can then obtain the corresponding ``demand behavior'' by representing
% the input demand as a free variable that is constrained to be an approximation
% of some actual input. Our main technical contribution is a proof that this
% approach does result in behavior that is equivalent to clairvoyance and demand
% semantics, respectively. This proof has also been formalized in Agda.
