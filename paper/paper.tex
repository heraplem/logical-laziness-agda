% There are two languages:
%   + 𝐁, the base language
%   + 𝐋, the logic language
% - \L<X> is the symbol for language X

% - There are five "semantics symbols":
%   + 𝔼, for exact values and evaluation semantics
%   + 𝔸, for approximation values
%   + ℂ, for clairvoyance semantics
%   + 𝔻, for demand semantics
%   + 𝕃, for logic semantics
% - \S<X> is the semantics symbol X

% - \T<X> is the type X
% - \S<X> is the set of values for the type X
% - \t<X> is the term (or term-level construct) X
% - \s<X> is the semantic construct <X>

% - \T<X> is also the typing relation for language X
% - \E<X> is the evaluation relation for semantics X
% - \trans<X> is the translation from B to L corresponding to semantics X

% - Macros are generally n-ary; i.e., the macro \TThunk for thunk types takes
% one argument, the type argument.  If we need a zero-arity version of macro M,

\maketitle

\begin{abstract}
  In functional logic programming, one program contains two semantics: a
  ``forward'' nondeterministic semantics with choices, and a ``backward''
  demand-driven semantics with free variables. But why is that useful? In this
  paper, we show that two independently discovered semantics that model the
  computation cost of lazy functional programs, namely the clairvoyance
  semantics of Hackett and Hutton and the demand semantics of Bjerner and
  Holmstr{\"{o}}m, correspond exactly to these two semantics of one functional
  logic program. We propose and formalize a mechanical translation strategy
  based on a simple typed calculus that produces a clairvoyance translation
  based on a simple logic language, and a demand translation that is a simple
  wrapper of the clairvoyance translation. We prove the translation strategy to
  be correct in Agda. We also conduct case studies based on common lazy
  functional programs to demonstrate how this approach can be applied to
  Curry/PAKCS.\@

  \keywords{Functional Logic Programming, Lazy Evaluation, Cost Analysis}
\end{abstract}

\section{Related work}\label{sec:related-work}

There are many other semantics for lazy programming languages. The best known of
these is the natural semantics of Launchbury,~\cite{launchbury1993} which models
the state of a lazy program as a heap of variable bindings that is updated
whenever a variable is evaluated.

Clairvoyance semantics was first studied by Hackett and
Hutton~\cite{clairvoyant}, who proved its equivalence with Launchbury's
semantics. Li \emph{et al.}\ developed a model of this semantics in Rocq, along
with a framework for proof automation\cite{forking-paths}. Our Curry model is
adapted from this work.

Demand semantics was first studied by Bjerner and
Holmstr{\"{o}}m.~\cite{bjerner1989} Their semantics was untyped; a typed version
was first published in Xia \emph{et al.}\cite{demand-semantics} Our demand
semantics is essentially the same as theirs. That work was also the first to
demonstrate that demand semantics is equivalent to other semantics for lazy
languages; in particular, it contains the theorems of cost existence and cost
minimality with respect to clairvoyance semantics.
